# Module 5.6 — PID-керування вентилятором за температурою

За основу взято код заняття: термістор (дільник напруги) читається через АЦП,
переводиться у температуру за формулою Стейнхарта-Харта, PID-регулятор тримає
її на рівні `SETPOINT_TEMP = 28°C`, керуючи обертами вентилятора через ШІМ
(LEDC, 5 кГц, 10-біт duty).

## Що було не так у вихідному коді

Коефіцієнти `Kp/Ki/Kd` були нульові — регулятор нічого не регулював, а знак
D-складової був переплутаний:

```c
float derivative = -(filtered_temp - fan_pid.prev_pv) / dt;
```

Контур тут **реверсивний**: `error = PV - SP`, тобто чим тепліше — тим більше
duty. Похідна похибки дорівнює похідній PV (SP стала), без зайвого мінуса.
З мінусом D-складова, навпаки, ГАЛЬМУВАЛА вентилятор саме тоді, коли
температура зростала найшвидше — регулятор діяв проти власної мети. Виправлено на:

```c
float derivative = (filtered_temp - fan_pid.prev_pv) / dt;
```

Тепер D-складова випереджувально піднімає обороти, коли температура ще тільки
розганяється вгору, і гасить розгін, коли вона різко падає.

## Підібрані коефіцієнти

| Коеф. | Значення | Обґрунтування |
|-------|----------|----------------|
| `Kp`  | 60.0     | Тепловий об'єкт повільний — повний duty (1023) досягається приблизно при +17°C похибки, це дає помітну, але не різку реакцію без миттєвого насичення виходу. |
| `Ki`  | 8.0      | Прибирає статичну похибку (термістор/повітряний потік ніколи не дадуть точного попадання на самому Kp), але накопичується повільно — за умовне-інтегрування (anti-windup) відповідає існуючий блок кондиційного інтегрування + кламп `out_max/Ki`. |
| `Kd`  | 25.0     | Демпфер: гасить перерегулювання й "розгойдування" навколо уставки, які типові для теплових об'єктів з інерцією (термістор реагує з затримкою відносно самого повітря). |

Це стартові значення для ручного налаштування на реальному стенді: дивитись
через `pio device monitor` на рядки `SP/PV/OUT/PWM`, і за необхідності
підкручувати — збільшувати `Kp` до появи легких коливань, потім додавати `Kd`
для їх гасіння, і підключати `Ki` в останню чергу, якщо лишається стала
похибка.

## Нормалізація виходу PID у сигнал керування

У вихідному коді вихід PID (`0..1023`) обрізався нижнім порогом
`MOTOR_MIN_PWM = 200`: усе, що нижче порогу, ставало `duty = 0`, а одразу
після порогу — стрибок на `200`. Це розрив у сигналі керування: невеличка
зміна похибки біля порогу давала стрибок duty на 200 одиниць.

Замість порогу весь діапазон виходу PID `[0, out_max]` лінійно
відображається (`normalize_pid_output_to_duty()`) у реальний робочий
діапазон ШІМ `[MOTOR_MIN_PWM, MAX_DUTY_CYCLE]`:

```c
uint32_t normalize_pid_output_to_duty(float output, float out_max) {
    if (output <= 0.0f) return 0;
    float normalized = MOTOR_MIN_PWM +
        (output / out_max) * (MAX_DUTY_CYCLE - MOTOR_MIN_PWM);
    ...
    return (uint32_t)normalized;
}
```

Тобто щойно вихід PID стає додатнім, вентилятор одразу отримує
`MOTOR_MIN_PWM` (мінімум, при якому мотор ще впевнено крутиться) і плавно,
пропорційно похибці, наростає до `MAX_DUTY_CYCLE`. Розриву в сигналі
керування більше немає.

## Апаратна конфігурація

| Сигнал              | Пін ESP32-S3 | Примітка                              |
|---------------------|--------------|-----------------------------------------|
| Термістор (дільник) | GPIO4        | ADC1, канал 3, атенюація 12 дБ          |
| Вентилятор (ШІМ)    | GPIO18       | LEDC, 5 кГц, 10-біт duty (0..1023)      |

Відкрити монітор порту на 115200 8N1 — щоцикл (50 мс) друкується рядок
`SP:.. PV:.. OUT:.. PWM:.. (..%)` для спостереження за реакцією регулятора.
